# 分镜脚本指南（灵活版）

## 核心理念

**重要的是描述质量，不是格式完美！**

只要分镜脚本包含足够的信息让视频 AI 理解，格式可以很灵活。

---

## 最小可用格式

### 方式 1：JSON（推荐，便于程序处理）

```json
{
  "id": "opening",
  "description": "一个精致的咖啡杯放在木质桌面上，柔和的晨光从左侧窗户投射进来，蒸汽缓缓上升。镜头缓慢推进，背景虚化。温暖、宁静的氛围。"
}
```

**只需要两个字段**：
- `id`：文件名/标识符（随意命名，如 `opening`、`01-intro`、`场景1` 都可以）
- `description`：视觉描述（这是最重要的！）

**可选字段**（有就更好，没有也行）：
- `duration`：时长（秒），如 5
- `title`：场景标题，如 "开场镜头"

### 方式 2：Markdown（更自由）

```markdown
## 开场镜头

一个精致的咖啡杯放在木质桌面上，柔和的晨光从左侧窗户投射进来，
蒸汽缓缓上升。镜头缓慢推进，背景虚化。温暖、宁静的氛围。

时长: 5秒
```

插件可以解析 Markdown，自动转换为 JSON。

### 方式 3：纯文本（最简单）

```
opening.txt:
一个精致的咖啡杯放在木质桌面上，柔和的晨光从左侧窗户投射进来，
蒸汽缓缓上升。镜头缓慢推进，背景虚化。温暖、宁静的氛围。
```

## 如何写好描述（这才是重点！）

视频 AI 的质量取决于提示词质量，不是 JSON 格式。

### 好描述的 5 要素

1. **场景（Scene）**
   - 在哪里？什么环境？
   - 例：木质桌面、咖啡厅、城市街道、森林

2. **主体（Subject）**
   - 画面中的主要对象
   - 例：咖啡杯、人物、产品、动物

3. **光线（Lighting）**
   - 什么样的光？
   - 例：柔和的晨光、金色的夕阳、霓虹灯、月光

4. **运镜（Camera Movement）**
   - 镜头如何移动？
   - 例：缓慢推进、环绕、俯拍、跟随

5. **动作/运动（Motion）**
   - 画面中有什么在动？
   - 例：蒸汽上升、人物走动、水流、风吹

6. **氛围（Mood）** - 可选
   - 情绪和感觉
   - 例：温暖、宁静、紧张、活力

### ⭐ 首帧提示（推荐）
- 在分镜元数据中增加 `- **首帧提示**: ...`
- 用 1-2 句话描述“故事开始的第一个画面”
- 必须使用静态画面语言，禁止出现“镜头/推拉/时间流逝/剪辑/切换”等术语
- 明确：单场景、无分屏、无文字/字幕/Logo
- 示例：`- **首帧提示**: 猪大哥气喘吁吁地敲木房子的门，衣服被风吹乱、满脸汗水，猪二哥在门内紧张地拉他进屋；这是一个没有文字的单场景画面。`

### 示例对比

❌ **差的描述**（太简单）：
```
一个咖啡杯
```

✅ **好的描述**：
```
一个精致的白色咖啡杯放在深色木质桌面上，
杯中升起缕缕白色蒸汽。
柔和的自然光从左侧窗户洒进来，
在桌面上投下温暖的光影。
镜头缓慢从远处推近到咖啡杯特写。
整体氛围宁静、温馨，充满清晨的美好感。
```

⭐ **更好的描述**（专业）：
```
画面：极简美学，深色胡桃木桌面纹理清晰可见
主体：手工陶瓷咖啡杯（白色，带细腻釉面），杯中咖啡呈深棕色
光线：侧逆光，golden hour 质感，光束穿过蒸汽产生丁达尔效应
运镜：dolly in（推轨前进），从 wide shot 到 close-up，速度缓慢平稳
动作：蒸汽垂直上升，速度适中，形态柔和飘逸
景深：大光圈，背景虚化（bokeh效果），焦点在咖啡杯上
色调：暖色调为主，米色、木色、金色
情绪：平和、专注、生活美学、慢节奏
参考风格：北欧极简风、生活方式摄影
```

## 插件的"宽松验证"

### 必须有的（否则无法处理）
- ✅ 文件必须是有效的 JSON（语法正确）
- ✅ 必须有 `id` 字段（用于命名视频文件）
- ✅ 必须有 `description` 字段（用于生成视频）

### 可以没有的（插件自动补充）
- ⚠️ 没有 `duration`？默认 5 秒
- ⚠️ 没有 `title`？用 `id` 作为标题
- ⚠️ `id` 格式随意？只要是字符串就行

### 友好的提示（不是错误）
- 💡 描述太短（<50字）→ 提示："描述较短，可能影响视频质量"
- 💡 没有提到运镜 → 提示："建议添加镜头运动描述"
- 💡 没有提到光线 → 提示："建议添加光线描述"

**不会阻止用户继续，只是善意提醒！**

## 验证逻辑（修订）

```typescript
interface StoryboardValidation {
  isValid: boolean;        // 能否使用
  errors: string[];        // 致命错误（阻止使用）
  warnings: string[];      // 建议（不阻止）
}

function validateStoryboard(json: any): StoryboardValidation {
  const errors = [];
  const warnings = [];
  
  // 致命错误（必须有）
  if (!json.id) {
    errors.push('缺少 id 字段');
  }
  if (!json.description) {
    errors.push('缺少 description 字段');
  }
  
  // 友好建议（可以没有）
  if (json.description && json.description.length < 50) {
    warnings.push('描述较短（建议 100 字以上），可能影响视频质量');
  }
  
  // 检查是否提到关键元素（非强制）
  const desc = json.description || '';
  if (!hasKeyword(desc, ['镜头', '推', '拉', '移', '摇', 'camera'])) {
    warnings.push('建议添加运镜描述（如：镜头推进、俯拍等）');
  }
  if (!hasKeyword(desc, ['光', '阳光', '灯光', 'light'])) {
    warnings.push('建议添加光线描述（如：柔和的光线、夕阳等）');
  }
  
  return {
    isValid: errors.length === 0,
    errors,
    warnings
  };
}
```

## 总结：简单 > 完美

### ❌ 错误的理念
- "JSON 格式必须完美"
- "必须通过所有验证"
- "字段名必须规范"

### ✅ 正确的理念
- **内容重于形式**：好的描述 > 完美的格式
- **宽松灵活**：只检查必需字段，其他都可选
- **友好提示**：建议而不是强制
- **快速迭代**：让用户尽快生成视频，不要被格式困住

## 给 AI 的最佳提示词

当用户让 AI 生成分镜时，这样说更好：

```
请根据剧本.md 生成分镜脚本。

要求：
1. 每个场景生成一个 JSON 文件
2. JSON 至少包含 id 和 description
3. description 要详细描述：场景、主体、光线、运镜、动作、氛围
4. 每个描述至少 100 字
5. 格式可以灵活，重点是描述质量

示例：
{
  "id": "opening",
  "description": "城市清晨，高楼玻璃幕墙反射金色阳光。无人机低空上升视角，展现天际线。街道车流如织，充满活力。"
}
```

这样 AI 会更关注内容质量，而不是纠结于格式细节。
